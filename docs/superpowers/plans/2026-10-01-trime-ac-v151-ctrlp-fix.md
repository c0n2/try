> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the two device-reproduced Ctrl+P failures in v1.5 without changing the v1.4 keyboard/Vim baseline or the Phase 1 lexicon data.

**Architecture:** Keep v1.5's add-word UX and encoding logic. Route all add-word dialog creation onto Android's main dispatcher, and perform `UserDictManager.importUserDict()` only while the active Rime instance is finalized so the LevelDB userdb lock is released; always restart Rime afterward while preserving daemon sessions.

**Tech Stack:** Kotlin, Android IME, kotlinx.coroutines, librime/levers, Python build harness, GitHub Actions.

**Spec:** Device log `Trime-AC-v1.5-CtrlP.log` from 2026-10-01 plus v1.5 branch `trime-ac-ctrlp-addword-v15`.

## Review Focus

- Dialog invocation from the Rime worker thread must always hop to `Dispatchers.Main.immediate` before any `EditText`/`AlertDialog` creation.
- User-dictionary import must occur after `realRime.finalize()` and before startup.
- Rime startup must execute from `finally`, including import failure paths.
- Existing daemon sessions must remain registered across maintenance.
- Failed startup must reuse the existing startup-retry path rather than leaving Rime permanently stopped.
